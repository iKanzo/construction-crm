# Архитектура

## Компоненты

- `frontend/` — React 18, TypeScript, Vite, React Router и TanStack Query. Точка входа монтирует `App`, который создаёт router и QueryProvider. Реальный маршрутный экран и основные сценарии находятся в `src/app/Crm.tsx`; старые компоненты-заглушки в `src/pages` и `RootLayout` не являются текущим маршрутизатором.
- `frontend/src/shared/api/supabase.ts` создаёт клиент Supabase из публичных `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, предоставляет вспомогательные функции чтения и вызова RPC.
- `backend/supabase/` содержит локальную конфигурацию, миграции PostgreSQL, seed и Edge Function `invite-user`. Supabase предоставляет Auth, PostgREST и Edge runtime. Конфигурация локальной БД использует PostgreSQL 17; Realtime и Storage отключены.

## Интерфейс и поток данных

`AuthGate` получает и отслеживает сессию, загружает профиль и не открывает приложение при отсутствии или деактивации профиля. Без сессии отображается форма входа/восстановления; при событии восстановления доступна установка пароля. После входа layout передаёт профиль и сессию дочерним маршрутам. `/login` для вошедшего пользователя перенаправляет на `/`, неизвестный путь — тоже на `/`.

Маршруты: `/` — объекты, `/objects/:objectId`, `/tasks/:taskId`, `/my-tasks`, `/transfers`, `/users`, `/profile`. Экран сотрудников доступен в UI администратору. На экранах предусмотрены управление объектами и задачами, назначение и переходы статусов, история, чат, передача ответственности, приглашение и деактивация сотрудников, смена пароля. Реальная доступность операций зависит от серверных правил и данных.

Чтение идёт через Supabase с RLS; изменения бизнес-данных вызывают SQL RPC. Приглашение вызывается через Edge Function. Query кэширует результаты и инвалидирует их после действий; комментарии и передачи опрашиваются каждые 5 секунд, профиль — каждые 30 секунд. Это polling, не Realtime.

## База и функции

Миграции по порядку создают схемы и привилегии, шесть таблиц (`profiles`, `objects`, `tasks`, `task_history`, `comments`, `transfers`), триггеры, RLS-хелперы и политики, затем бизнес-RPC. RPC охватывают объекты, задачи, назначения и статусы, передачи, деактивацию и комментарии; точные правила задаёт SQL. История и комментарии защищены от изменения и удаления триггерами. Запросы выполняются в контексте PostgreSQL; безопасность не должна опираться на скрытие элементов интерфейса.

`invite-user` проверяет Auth и активного администратора, затем серверным ключом вызывает Auth Admin API и создаёт профиль. Эти две операции не атомарны: ошибка создания профиля требует ручной сверки. Подробнее о правах и рисках — [SECURITY.md](SECURITY.md).
